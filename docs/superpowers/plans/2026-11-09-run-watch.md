# The Lead Watches the Run: Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** While a `crew run` goes, the lead tells the owner about every item that newly waits on them, and when the run ends it reports the summary, closes the run pane and goes through the inbox.

**Architecture:** The supervisor appends JSON events (`start`, `item`, `end`) to `.crew/run-events.jsonl`, computed from the snapshot it already takes each tick. A new `crew watch` command follows that file (no GitHub calls) and prints one human-readable line per event. It exits after the end. The lead runs `crew watch` with Claude Code's Monitor tool, so each line reaches it while the owner keeps talking to it.

**Tech Stack:** Python 3.12, argparse, pytest, ruff; Markdown skills and agents in `plugins/crew`.

**Spec:** `docs/superpowers/specs/2026-11-09-run-watch-design.md`

## Global Constraints

- No push, desktop or phone notifications; the lead's pane is the only channel.
- `crew watch` makes no GitHub calls; it reads only `.crew/run-events.jsonl` and `.crew/run.json`.
- Live items never mark the inbox as seen (the watcher doesn't touch `.crew/state.json`).
- Items already waiting when the run starts produce no `item` event; one `item` event per `(number, ask)` that is new compared with the previous tick.
- Dry runs (`--dry-run`) write no events and don't truncate the file; non-dry `--once` runs are not watched (they write `start`/`item` events, but no `end`).
- The events file is truncated only after `_adopt` succeeds, so a rejected second `crew run` leaves a live run's events alone.
- Every PR or issue the watcher prints carries its full URL.

## Review Focus

- **The lead starts `crew watch` a moment before `crew run` has written its `start` event**: the old file still holds a reported run. Expected: the watcher waits (up to `START_WAIT` = 60 s) for the new run instead of saying "nothing to watch". Test in Task 3.
- **The run process is killed or crashes (no `end` event)**: expected exit code 2 and a line saying the run stopped without an end report, so the lead leaves the pane open. Test in Task 3.
- **An item leaves the inbox and comes back on a later tick** (for example, the owner answers and the agent asks again): expected a fresh `item` event, because it newly waits again. Test in Task 2.
- **`crew watch` twice on the same ended run** (a second lead session): expected the end report the first time only; the second prints "nothing to watch" and exits 1. Test in Task 3.
- **A run that ends with an error** (`_wind_down("error: …")`): expected the `end` event to have `error: true` and the watcher's end line to read `run ended: error: …`. Test in Task 2.

### Task 1: Event log module and gitignore entry

**Files:**
- Create: `src/crew/supervisor/events.py`
- Modify: `src/crew/init.py:8` (`GITIGNORE_ENTRIES`)
- Test: `tests/supervisor/test_events.py`, `tests/test_init.py`

**Interfaces:**
- Produces:
  - `EVENTS_PATH = Path(".crew") / "run-events.jsonl"`
  - `def new_run_id(pid: int, started: datetime) -> str`, formatted as `f"{pid}-{started:%Y%m%dT%H%M%SZ}"` (UTC)
  - `def start_log(root: Path, run_id: str, at: datetime, until: datetime, pane: str | None) -> None`: truncates the file and writes the `start` event
  - `def append_event(root: Path, event: dict) -> None`: appends one JSON line. Not atomic, so the writer must open the file in append mode and write one `json.dumps(event) + "\n"` per call.
  - `def read_events(root: Path) -> list[dict]`: skips lines that don't parse, such as a half-written last line. A missing file gives `[]`.
  - `def format_event(event: dict) -> list[str]`: the human-readable lines (below)
- Event shapes (all carry `"run": run_id`, `"type"` and `"at"`, an ISO 8601 UTC string):
  - `start`: `until`, `pane` (str or null)
  - `item`: `number`, `ask`, `title`, `url`
  - `end`: `reason`, `error` (bool), `pane`, `started`, `finished`, `stuck`, `paused` (lists of the strings `_Summary` already holds)
  - `reported`: no extra fields
- `format_event` output, with the time as local `HH:MM` like `Supervisor._log`:
  - `item`: `["14:05 waiting on you: #12 [accept] Add login — https://github.com/example/app/pull/40"]`
  - `end`: `["14:05 run ended: <reason>"]`, then for each non-empty list in the order Started, Finished, Stuck, Paused, a `"<Title>:"` line and `"  <entry>"` lines, then `"run pane: <pane>"` when `pane` is set
  - `start`: `["14:05 run started, until <until local %a %H:%M>"]`
  - `reported`: `[]`

- `_wind_down(reason)` appends the `end` event after `_print_summary`, with `error = reason.startswith("error: ")`.
- With `run_id` unset (dry run), nothing is written.

### Task 3: `crew watch`

**Files:**
- Create: `src/crew/watch.py`
- Modify: `src/crew/cli.py` (new `watch` subcommand and `_cmd_watch`)
- Test: `tests/test_watch.py`

**Interfaces:**
- Consumes: `EVENTS_PATH`, `read_events`, `append_event`, `format_event` (Task 1); `RUN_PATH`, `_is_crew_run` (`loop.py`; rename it to public `is_crew_run` and update its callers); `run.json`'s `run_id` and `pid` (Task 2).
- Produces:
  - `def run_status(root: Path, alive: Callable[[int], bool] = is_crew_run) -> Literal["active", "ended", "none"]`. Meaning: `active` when `run.json` has a pid that `alive` accepts. `ended` when the latest run's events hold an `end` but no `reported`. `none` otherwise.
  - `def watch(root: Path, replay: bool, out: Callable[[str], None] = print, sleep: Callable[[float], None] = time.sleep, alive: Callable[[int], bool] = is_crew_run, clock: Callable[[], float] = time.monotonic) -> int`
  - CLI: `crew watch [--replay] [--status] [--root PATH]`. Help: `"follow the active run: new owner items and the run's end (for the lead)"`. `--status` prints `run_status`'s word and returns 0.
  - Constants: `POLL = 2` (seconds between reads), `START_WAIT = 60` (seconds to wait for a run to appear).

**`watch()` behavior:**
1. **Wait for a run.** Poll until one is active (a live pid whose `run.json` `run_id` equals the `run` of the file's first event, a `start`) or the latest run is `ended`. Give up after `START_WAIT` seconds: print `"nothing to watch: no active run and no unreported end"` and return 1.
2. **Choose the starting position.** With `replay`, print every event so far through `format_event`, then the line `"--- live from here"`. Without `replay`, skip the `item` events already in the file. An `end` already in the file is still printed.
3. **Follow.** Each `POLL`, read the events and print the new ones in order.
4. **On the `end` event.** Print it, append `{"run": id, "type": "reported", "at": now}` and return 0.
5. **If the pid is no longer alive and there is no `end`.** Re-read once. If there is still no `end`, print `"run stopped without an end report (pid N); its pane shows why"` and return 2.
